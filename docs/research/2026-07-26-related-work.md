## 1. 가장 가까운 공개 프로젝트: DaleSeo/korean-skills

2026년 공개. AI 에이전트용 스킬 저장소로 두 스킬이 직접적으로 겹친다.

- `grammar-checker`: 한국어 맞춤법, 띄어쓰기, 조사·어미, 구두점 검사
- `style-guide`: 프로젝트 전체의 어조, 용어, 숫자·단위, 목록, 따옴표, 날짜, 링크 형식 일관성 검사.
  `사용자 ↔ 유저` 용어 혼용, 외래어 표기 혼용, 기술 문서별 스타일 적용까지 명시.

**차이점**: 공개 저장소 기준으로 독립 분석 프로그램이 아니라 *LLM에게 검사 방법을 지시하는
SKILL.md + 참고 규칙 묶음*이다. 문서 AST, 형태소 분석 IR, 정확한 소스 위치 추적, 결정적 규칙
실행기, 증분 분석 같은 엔진은 없다.

```text
DaleSeo style-guide:  문서 + 프롬프트 → LLM이 전체적으로 검토하고 재작성
이 프로젝트:          저장소 → 파싱·인덱싱·참조 해석 → 재현 가능한 진단
```

→ **용어 통일·문체 검사만으로는 이미 겹친다. 엔진 구조와 평가 체계가 핵심이어야 한다.**
→ 베이스라인 비교 대상 1순위. 정확도·재현성·진단 위치·처리 속도·오탐률에서 무엇을 더
제공하는지 실험할 것.

- https://github.com/daleseo/korean-skills

## 2. 한국어 상용·사용자용 교정 도구

- **네이버 스마트보드**: 입력 중 맞춤법·띄어쓰기 검사. 문서 저장소의 용어 정의·지시 관계
  분석 도구는 아님.
- **부산대 인공지능연구실 + 나라인포테크 맞춤법·문법 검사기**: 대표적인 한국어 교정 도구.
  기본 단위는 사용자가 입력한 텍스트의 맞춤법·문법 교정. (공식 사이트가 조사 시점에 정상적으로
  열리지 않아 세부 기능은 독립 검증 못 함.)

기존 사용자용 서비스의 분석 단위:

```text
문장 입력 → 잘못된 부분 탐지 → 교정문 제안
```

이 프로젝트의 분석 단위:

```text
여러 Markdown 문서 → 문서 구조·용어 정의 인덱싱 → 문서 간 관계·참조·불일치 분석
```

## 3. 한국어 문법 교정(GEC) 연구

### KAGAS (ACL 2023)

- 한국어 문법 오류를 **14가지 유형**으로 정의
- `Kor-Lang8`, `Kor-Native`, `Kor-Learner` 세 데이터셋 구축
- 원문·교정문을 비교해 오류 유형을 자동 주석하는 시스템 + 평가 벤치마크 공개
- 활용처: 오류 분류 체계 참고, 원문–수정문 정렬, 조사·어미·띄어쓰기 오류 평가,
  기존 한국어 GEC 모델과의 베이스라인 비교
- 한계: 목표가 *문법적으로 틀린 문장 교정*. 문법적으로 맞지만 모호한 문장, 문서 간 용어
  정의 충돌은 주된 대상이 아님.
- https://aclanthology.org/2023.acl-long.371/

### KAGEC (EMNLP 2024 Findings)

- LLM이 한국어 문법 지식을 내부 파라미터에만 의존하면 부족하다고 보고, 문장에서 핵심 표현을
  추출한 뒤 **외부 근거를 검색해 교정 프롬프트에 제공**
- 대부분의 실험 모델이 외부 근거 제공 시 성능 향상 보고
- **조사표와의 접점**: 조사표에는 교정안뿐 아니라 국립국어원 근거와 판정 이유가 있으므로,
  결과만 생성하는 대신 근거를 검색해 진단에 연결하는 구조가 가능
- https://aclanthology.org/2024.findings-emnlp.6/

### KoGEC (PACLIC 2024)

- 사전 학습 번역 모델을 한국어 교정에 미세 조정. `오류 한국어 → 교정 한국어` 번역 문제로
  접근하는 계열.
- 이 계열은 교정 정답 문장 *생성* 모델에 가깝고, 작성자에게 구조화된 정적 진단을 제공하는
  개발 도구와는 거리가 있음.
- https://aclanthology.org/2024.paclic-1.16/

## 4. 한국어 상호참조(coreference) 연구

`해당 데이터`, `이 값`, `그 결과`의 지시 대상 찾기는 이미 연구된 문제.

- 2001년: 정보 추출을 위한 휴리스틱 기반 한국어 상호참조 해결
  (https://aclanthology.org/Y02-1005/)
- 2020년: 한국어의 핵어 후행 특성을 이용한 BERT-SRU Pointer Network.
  ETRI 테스트셋 CoNLL F1 66.9%, 문서 처리 속도 30건/초 보고.
- 2024년: `KoCoNovel` — 한국 현대소설 50편, 약 17.8만 토큰의 등장인물 상호참조 주석.
  한국어는 인명 반복보다 친족·사회관계 명사로 사람을 지칭하는 특징 분석.
  (https://arxiv.org/abs/2404.01140)

**핵심 차별화**: 기존 연구 목표는 "여러 표현이 같은 개체를 가리키는지 맞힌다".
이 프로젝트의 목표는 **"작성 시점에 후보가 여러 개여서 독자가 혼동할 위험이 있는지 탐지"**.
엔진이 억지로 `해당 데이터 = 조인 결과`로 결정하는 대신:

```text
REF101: '해당 데이터'의 지시 대상이 불명확합니다.

가능한 후보:
- 사용자 테이블
- 주문 테이블
- 두 테이블의 조인 결과

제안: '조인 결과를 저장합니다.'처럼 대상을 직접 쓰세요.
```

→ 상호참조 해결 기법을 *이용*하되, 목적은 **모호성 탐지**.

  의존 구문 분석(어절 간 지배 관계·격 관계), 의미역 인식 제공.

- **Kiwi**: 공개 한국어 형태소 분석기. 세종 품사 체계, 문장 분리, 사용자 사전, 간단한 오타
  교정 지원. 로컬에서 반복 실행하는 개발 도구에는 외부 API보다 Kiwi 우선이 현실적.
  (https://github.com/bab2min/kiwi)

권장 파이프라인:

```text
Markdown parser → Kiwi 형태소·문장 분석 → 자체 Document IR → 용어·참조·모호성 분석
```

## 6. 이번 검색에서 찾지 못한 것 (= 빈 공간)

한국어 기준으로 아래를 한꺼번에 구현한 공개 프로젝트는 검색 범위에서 발견하지 못함:

- Markdown/MDX 저장소 단위 파싱
- 정확한 파일·줄·열 진단
- 프로젝트 용어 정의·참조 인덱스
- 여러 문서 사이의 용어 정의 충돌 탐지
- `해당 데이터` 같은 참조 표현의 모호성 진단
- 조직별 규범·관용 프로필
- LSP·SARIF·PR 코멘트 통합
- 한국어 기술 문서 전용 평가 데이터

특히 **한국어 기술 문서·요구사항 문서의 모호성을 작성 단계에서 검사하는 공개 연구·엔진**은
뚜렷한 것을 찾지 못함. 단, "없다"를 완전히 증명할 수는 없으므로 `최초` 주장 대신 기존
작업과의 차이를 명확히 기술할 것.

## 7. 포지셔닝 (수정판)

신규성을 한국어 문법 검사나 스타일 일관성 *자체*에 두면 안 된다(이미 존재). 핵심 세 가지:

1. **저장소 단위의 용어·개념 그래프** — 정의·별칭·참조·충돌 인덱싱
2. **지시 대상 '정답 맞히기'가 아닌 '해석 위험' 탐지** — 후보 간 확신도 차이가 작을 때 경고
3. **실제 기술 문서 벤치마크** — KAGAS는 일반 원어민·학습자 문장 중심. 실제 기술 블로그에서
   모은 원문·수정안·오류 분류·판정 이유·공식 근거·확신도·문서 장르 필드를 갖춘 조사표를
   한국어 기술 문서 품질 벤치마크로 발전

공식 포지셔닝 문장:

> 기존 한국어 문법 교정 시스템은 문장 수준의 오류 수정에, 최근 AI 스타일 검사기는 LLM 기반의
> 전체 문서 검토에 집중한다. 이 프로젝트는 한국어 기술 문서 저장소를 파싱하여 용어 정의·참조·
> 문서 간 일관성을 인덱싱하고, 모호한 참조와 정의 충돌을 재현 가능한 진단으로 제공한다.

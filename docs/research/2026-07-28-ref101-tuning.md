# REF101 튜닝 챕터 (스펙 §6.3) — 2026-07-28

스펙 §6.3: "가중치·임계값은 하드코딩하지 않고 설정 파일로 분리해 벤치마크로 튜닝한다.
튜닝 과정 자체가 실험 리포트의 한 챕터가 된다." 이 문서가 그 챕터다.
전제 측정: [외부 코퍼스 발화율·오탐 유형](2026-07-28-external-corpus-fp.md).

## 방법

세 지표를 동시에 본다 — 오탐 프록시는 내리고, 진짜 양성 가드는 지킨다:

| 지표 | 데이터 | 역할 |
|---|---|---|
| seed F1 / REF recall | 시드 벤치 8문장 (문맥 포함, 라벨 있음) | recall 가드 |
| fixture golden | data-platform 픽스처 (TERM101·102 + REF101 + clean 파일) | 회귀 가드 |
| 발화 건수/1,000줄 | fe-news 15,921줄 · ko.react.dev 119,917줄 (라벨 없음) | 오탐 프록시 |

스윕 도구는 `benchmark/sweep_ref101.py` (코퍼스를 한 번 파싱하고 config별로 분석만
재실행). 재현: `uv run python benchmark/sweep_ref101.py <코퍼스경로 ...>`.

## 단계 1 — 규칙적 처리 (점수 이전의 구조 개선)

외부 측정의 표본 판정(20건 전부 실질 오탐, 유형 3종)이 가리킨 대로, 점수로 해결되지
않는 클래스를 규칙으로 먼저 제거했다:

| 개선 | 내용 | 근거 오탐 클래스 |
|---|---|---|
| 인라인 코드 마스킹 (스펙 §5) | 코드 스팬을 같은 길이 더미로 치환해 Kiwi 입력에서 제외 (오프셋 불변; 최초엔 공백, round-3에서 라틴 더미로 교체) | 식별자의 명사구 유입, 코드 내 마침표의 문장 분절 |
| 구조 참조 억제 | 지시어 뒤 명사/head가 글·문서·예시·코드·데모… 목록이면 침묵 (`reference.suppress_heads.structural`) | '이 글'·'위 예시 앱' — 선행사가 링크·코드블록·문서 자체 |
| 담화 지시 억제 | 문제·경우·방법·원칙·변화… 목록 (`reference.suppress_heads.discourse`) | '이 방법' — 선행사가 명제 |

효과 (threshold 0.2, 기본 가중치): fe-news 461→234 (−49%), react 1,709→1,204 (−30%).
목록은 config로 조정·비활성 가능하며, 시드·픽스처 가드는 불변.

## 단계 2 — 파라미터 스윕

| config | seed F1 | seed REF recall | fixture | fe-news/1k줄 | react/1k줄 |
|---|---|---|---|---|---|
| 억제 off · round-1 가중치 · th 0.2 (round-1 동작) | 0.750 | 1.00 | pass | 463 (29.1) | 1716 (14.3) |
| round-1 가중치 · th 0.2 | 0.750 | 1.00 | pass | 234 (14.7) | 1199 (10.0) |
| round-1 가중치 · th 0.15 | **0.571** | **0.00** | **FAIL** | 180 (11.3) | 834 (7.0) |
| round-1 가중치 · th 0.10 | 0.571 | 0.00 | FAIL | 175 (11.0) | 789 (6.6) |
| round-1 가중치 · th 0.05 | 0.571 | 0.00 | FAIL | 135 (8.5) | 635 (5.3) |
| head_match 0.45 · th 0.2 | 0.750 | 1.00 | pass | 199 (12.5) | 1045 (8.7) |
| head_match 0.45 · th 0.15 | 0.750 | 1.00 | pass | 189 (11.9) | 995 (8.3) |
| head_match 0.45 · th 0.10 | 0.571 | 0.00 | pass | 127 (8.0) | 603 (5.0) |

(round-1 가중치 = distance 0.4 · role 0.25 · head_match 0.25 · recency 0.1 —
스윕 스크립트에 **명시적으로 고정**되어 있어 default.yaml이 바뀌어도 베이스라인
행이 따라 움직이지 않는다. head_match 0.45 변형: distance 0.3 · role 0.15 ·
head_match 0.45 · recency 0.1. '억제 off' 행은 마스킹이 항상 켜져 있어 round-1
실측(fe-news 461=29.0/1k, react 1,709=14.3/1k)과 ±2 오차.)

**발견 1 — threshold 단독 튜닝은 절벽이다.** 0.2→0.15만 내려도 시드의 진짜 양성
('해당 데이터', 1·2위 점수차 0.18)이 임계값 아래로 떨어져 recall이 0이 된다. 오탐이
줄어드는 속도보다 진짜 양성이 먼저 죽는다 — 외부 측정의 "threshold 민감도" 절이
예고한 대로, 잔존 오탐은 점수 분포가 아니라 클래스의 문제다.

**발견 2 — head_match 증강은 순이득.** '이 툴팁'(1위 후보 '툴팁' 0.82가 head 일치인데
2위와 근소차로 발화)류의 '자명한 1위' 오탐을 정확히 겨냥한다: head 일치 1위의 점수차가
벌어져 침묵하고, 시드·픽스처의 진짜 양성은 유지된다. 같은 threshold에서 오탐 프록시만
−15%/−13% 추가 하락. th 0.15까지도 가드가 버티지만, 가드 데이터가 작아(시드 8문장)
절벽에서 먼 0.2를 유지한다.

## 확정 기본값 (default.yaml 반영)

`threshold 0.2 · weights {distance 0.3, role 0.15, head_match 0.45, recency 0.1}`
+ suppress_heads 목록 + 인라인 코드 마스킹.

**종합 효과: round-1 실측 대비 fe-news 29.0→12.5/1,000줄 (−57%), react
14.3→8.7/1,000줄 (−39%), 시드 F1 0.750·픽스처 golden 불변.**
(react 수치는 round-3의 명사 런 간격 수정 — 마스킹 영역을 런이 건너뛰던 결함 —
반영 후 값. 수정 전 표는 1050/8.8이었다.)

## 한계

- 오탐 프록시는 라벨이 없다 — 발화율 하락이 곧 정밀도 상승의 증명은 아니다
  (표본 재판정은 round-3 후보)
- recall 가드가 작다 (시드 8문장 + 픽스처 1세트) — 픽스처 확장과 함께 재스윕 필요
- 억제 목록은 측정 코퍼스에서 유도했다 — 폐쇄 부류(메타담화 명사)라 일반화 근거는
  있지만, 새 장르에서 목록 밖 구조어가 나올 수 있다 (config로 보완 가능)
- **억제는 recall도 깎는다**: '조인 방법과 정렬 방법 … 해당 방법'처럼 구체적 NP
  선행사 둘이 경쟁해도 head가 담화 목록에 있으면 침묵한다 (특성 테스트로 핀).
  round-3 후보: 윈도에 same-head 후보가 있으면 억제를 해제하는 예외. 잔존 발화
  재판정 시 이 클래스(억제로 잃은 진짜 모호)도 함께 표본화할 것
